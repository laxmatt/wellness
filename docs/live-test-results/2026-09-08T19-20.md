## Root cause: confirmed

**The application's requests never reach OpenAI. They are refused by the egress
proxy before they leave, because Node's built-in `fetch` does not use
`HTTPS_PROXY`, and credential injection only happens on the proxied path.**

Four observations, same host, same session, minutes apart:

| Client | Proxy path | Status | Body |
| --- | --- | --- | --- |
| `curl` (uses `HTTPS_PROXY`) | explicit CONNECT | 403 | OpenAI JSON, names the key's scopes |
| `curl --noproxy '*'` | transparent intercept | 403 | `text/plain`: `Host not in allowlist: api.openai.com.` |
| `node` default fetch | transparent intercept | 403 | `text/plain`: `Host not in allowlist: api.openai.com.` |
| `node` with `NODE_USE_ENV_PROXY=1` | explicit CONNECT | 403 | OpenAI JSON, names the key's scopes |

The proxied responses carry `Openai-Processing-Ms`, `X-Request-Id` and
`X-Proxy-Error: upstream denied the request: connection "OpenAI wellness test",
host "api.openai.com"`. The transparent ones carry none of that: the interceptor
answers, OpenAI is never contacted, and no credential is attached.

The application runs under `next start` on Node 22.22 with no
`NODE_USE_ENV_PROXY`, so it takes the transparent path. Its 403 body was
`text/plain`, which is why `statusError` could not treat it as provider evidence
and settled it `uncertain`. Every observation from both runs fits this and
nothing contradicts it.

### This corrects an earlier claim

The readiness check before run 1 concluded the application would reach the proxy
correctly. That was tested by fetching `openai.com`, a host absent from the
allowlist entirely, and reading the proxy's refusal as proof the proxy was in
path. It was in path. It was refusing. The test could not tell the two apart
because it used a host that would be refused either way. The correct test was
the allowed host on the same client the application uses.

### The fix

Start the server with `NODE_USE_ENV_PROXY=1` so Node's `fetch` uses the
CONNECT proxy that carries the credential. Verified above at zero cost, from
Node, on this machine. Nothing in `src/` changes.

This is a property of running under a Claude Code cloud environment, not of this
application, and it applies to any outbound call the server makes there.
