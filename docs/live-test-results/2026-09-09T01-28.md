## What this run was for: strict structured outputs

Appended by hand after the run. The section above is generated by
`src/domain/livetest-report.ts`, which knows nothing about `response_format`.

**The account and the model compiled the schema.** `ASSISTANT_RESPONSE_FORMAT=json_schema`
was set on the server, so the request carried
`response_format: {type: "json_schema", json_schema: {name: "model_intent", strict: true, schema}}`.
The provider answered 200 and the reply parsed on the first attempt. This was
the one question non-paid tests could not answer: they check the schema's shape
and check that every value branch it offers is one `ModelIntent` accepts, but
not whether OpenAI compiles it. It does, for `gpt-4o-mini` on this account, at
this date.

A schema strict mode refuses comes back as a 400 before inference, which
`statusError` settles as `not_billed`. That did not happen.

**The constraints, in the units the engine compares:**

| Constraint | Extracted | Asked for |
| --- | --- | --- |
| `price` | `lte 500000` | at most 500000 cents |
| `chiller_included` | `eq true` | true |

Both are read from the route's `apply_preferences` proposal, not from the
model's prose. `lte 500000` admits exactly $5,000 and nothing above it.

This is the extraction that failed twice before. The run of 21:37 returned
`{"key":"chiller_included","op":"true","value":true}`, the value written into
the operator field, and a bare number for the budget. Both are now correct.
One request is one request: it is evidence the schema works, not proof the
error cannot recur.
